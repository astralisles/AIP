# TLS (T-0989)

- `tlsConnect(host, port) -> TcpConn` (effect `tcp.connect`): TCP connect plus TLS handshake as client. The server certificate is validated
  against the system trust store and must match `host`; otherwise the call fails. There is no way to turn validation off.
- `tlsAccept(conn, pfxFile, password) -> TcpConn` (effects `tcp.accept`, `file.read`): upgrades a connection from `tcpAccept` to a TLS server
  connection using a PKCS#12 (`.pfx`) certificate.
- The result is a normal `TcpConn`: `tcpSend`, `tcpReceive`, `tcpClose` work unchanged and carry encrypted data.
- Example `examples/tls`, test `tests/checks/tls.ps1` (AIP server with a .NET TLS client; AIP client rejects a self-signed certificate).
- Not done: client certificates, custom trust roots, PEM files, UDP (DTLS), the interpreter (`aip run` uses the compiled C# like tcp).
